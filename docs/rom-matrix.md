## 已知特例（roadmap 登记）

1. **MIUI / HyperOS**：安全设置弹窗样式与通知样式差异（影响引导截图与 FGS 通知）；另有「USB 调试（安全设置）」类开关历史包袱。
2. **ColorOS**：权限监控激进，后台弹出界面/悬浮窗权限可能默认收紧，引导文案需按实测补。
3. **HarmonyOS（无无线调试入口）**：官方 Shizuku 依赖 WLAN 配对的机型无法激活——**shizuku-m 的离线自连恰是本项目的解法**，此类机型反而是目标用户；实测确认激活链。
4. **官方版 Shizuku 冲突**：任何 ROM 通用——同包异签不可覆盖装，App 内已有劝换引导（M4-b）；冲突分支真机演练（卸 shizuku-m 装官方版）随本矩阵一起做。

## 测试规程（每 ROM 一遍）

1. 装 shizuku-m → 启动（不连 WLAN/电脑）。
2. 装 AzurPilot → 引导授权 → 首启部署 → 热更新（含断网降级抽查）。
3. VD 建屏 + 桥 screencap×30（对照 >1s 线；基线 30ms）。
4. 悬浮窗面板：状态行 / 开始·停止 / 日志板。
5. 长稳挂机 2~3h（依赖演示通过后的标准负载），息屏子项需用户授权。
6. 重启 → 30 秒手动链恢复。
