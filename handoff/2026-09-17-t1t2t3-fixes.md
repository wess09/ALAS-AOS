## 核心决策（用户拍板，后续同类问题照此办理）

- **不为 AzurPilot 改代码，只为 AzurPilot 筑环境。** T2 选关崩溃第一方案是 template.py 通道归一补丁，用户否决："本软件要做的就是为 azurpilot 构筑好环境可以跑通功能，不要越俎代庖"。终案=把 rootfs 环境钉回上游钉版（imageio==2.27.0），补丁双源删除无痕。**今后凡 AzurPilot 内部缺陷，先查"环境与上游钉版是否一致"，再想补丁。**

## 三项修复终态（全部真机验证通过）

1. **T1 保屏**：`MainActivity.kt` 按 `runnerAlive || toolAlive` 加减 `FLAG_KEEP_SCREEN_ON`。dumpsys 双态实证。
2. **T2 选关崩溃**：根因=rootfs 烘焙装了不钉版 imageio 2.37.x（2.35+ 把 P 模式 GIF 模板解码成 RGB 3 通道），上游钉 2.27.0（首帧 2D 调色板索引）；`campaign_ocr.py:266 matchTemplate` 通道不一致断言。修复：
   - `rootfs/build/build-rootfs.sh` 钉 `imageio==2.27.0`；
   - 新增 `rootfs/seeds/env_fix.sh`（双源 `app/app/src/main/assets/azurpilot/overlay/seeds/env_fix.sh`）：每次启动自检钉版（pip + aliyun 镜像，失败不阻塞）+ 白名单 `git checkout -- module/base/template.py` 还原旧补丁遗留（单路径，绝不整树）+ mark 写 `log/env_fix.txt` + 永远 exit 0；
   - `ProotHost.kt` 启动链接入 env_fix，`ENV_FIX_TIMEOUT_MS=300_000`（proot 下 pip 慢一个量级，60s 会被杀）。
   - 验证：PC 对照（2.37 复现断言 / 2.27 命中 3 徽章）+ 真机 E2E（GemsFarming 选关 OCR 点中 d3 进图开战，无 cv2 error）。
3. **T3 半自动点击**：黑帧孤儿场景（游戏进程活着但 VD 全黑，App 重装/VD 重建后）此前修复失效。runner.py daemon 分支加判：游戏在跑**且**画面非黑帧（`mean()*3 >= 1.0`，对齐 AzurPilot check_screen_black）才跳过 pre-start。热/冷双分支真机验证。
